# Current data model

This schema is reconstructed from `Code.gs`. It must be checked against the
real spreadsheet headers before migration scripts are written.

## Players

```text
player_id | name | pin | email | active | created_at
```

PINs are currently stored as plain sheet values. A future authentication
migration should avoid returning or logging them and should not send them in a
query string.

## Matches

```text
match_id | round | stage | matchday | home_team | away_team |
kickoff_datetime | status | home_score_90 | away_score_90 |
actual_qualifier | actual_qualification_method | actual_first_scorer
```

Known `stage` values are `group` and `knockout`. Known statuses include
`upcoming`, `finished` and `void`.

## Predictions

```text
prediction_id | player_id | match_id |
pred_home_score_90 | pred_away_score_90 |
predicted_qualifier | predicted_qualification_method |
predicted_first_scorer | submitted_at | updated_at | points
```

The intended unique key is `(player_id, match_id)`, but it is not currently
protected by a database constraint or an Apps Script lock.

## Leaderboard

```text
rank | player_id | player_name | total_points | exact_scores |
correct_outcomes | qualifier_hits | method_hits |
predictions_submitted | missed_predictions | last_matchday_points |
most_wrong_prediction | updated_at
```

This sheet is fully regenerated by `recalculateAll()`.

## Settings

```text
setting | value
```

Settings referenced by code include:

- `lock_minutes_before_kickoff`
- `show_predictions_after_lock`
- `scoring_exact_score`
- `scoring_qualifier`
- `scoring_first_scorer`
- `prediction_website_url`
- `admin_email`

The scoring function currently contains numeric values directly in code, so
not all Settings values actually control scoring yet.

## Squads

```text
team | pos | player_name
```

Used to build first-goalscorer options for editable knockout matches.

## Audit_Log

Rows are appended in this order:

```text
timestamp | action | player_id | match_id | old_value | new_value | source
```

## Current API actions

| Action | Purpose | Mutates data |
|---|---|---:|
| `login` | Checks name and PIN | audit log only |
| `getMatches` | Returns fixtures and relevant predictions | No |
| `submitPrediction` | Creates or updates a prediction | Yes |
| `getLeaderboard` | Returns computed leaderboard | No |
| `getMatchPredictions` | Legacy prediction endpoint | No |
| `recalculateAll` | Rewrites points and leaderboard | Yes |
| `generateReminderMessage` | Builds reminder text | No |

## Serie A extensions proposed

Add `competition_id` and `season_id` to matches and predictions. Use a league
stage such as `league`, retain `matchday` for values 1–38, and make knockout-only
fields optional. Store a provider match ID so rescheduled fixtures and result
sync do not rely only on team names.
